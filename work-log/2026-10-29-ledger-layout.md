## 판단

- 같은 모양의 둥근 카드가 반복되는 구성을 걷어내고, 식당에 실제로 있는 두 가지를 모티프로 삼았다.
  - **예약 장부**: 예약·웨이팅 목록은 왼쪽에 시간(또는 대기번호) 열, 오른쪽에 내용을 두는 줄 목록. 목록 머리는 굵은 선, 줄 사이는 가는 선.
  - **번호표**: 화면에서 가장 강조하는 요소는 하나만 — 내 웨이팅의 대기번호와 예약 상세. 노랑 표에 양옆 홈과 절취선.
- 회색 8px 구분 띠 대신 여백과 제목 위계로 구역을 나눈다. 시간·번호·금액은 고정폭 숫자(`tnum`).
- 홈 첫 화면은 "언제, 몇 명이 가세요?" — 날짜 7일·시간·인원을 고르면 빈자리 검색(`?date&time&party`)으로 이동. 백엔드 검색 조건 그대로.

## 후속 (2026-10-29): 사용자 피드백 반영

사용자 요청: 여러 개 놓이는 항목은 선 대신 둥근 블록으로, 검색·마이다이닝은 연한 회색 바탕에 흰 블록, 홈·MY 는 선으로 구분, `·`·`—` 같은 기호를 쉼표로, 음식점 추천 서비스라는 점을 살리기. 홈은 배달 앱, 마이다이닝은 주문내역 화면을 참고.

| 영역 | 변경 |
| --- | --- |
| 공통 | `Card` 를 둥근 흰 블록으로 되돌림, `Page muted`(회색 바탕, 블록 테두리 없음), `StatLine` 을 둥근 블록으로, `Divider thick` 을 회색 띠로, 검색 탭에서도 하단 탭 표시 |
| 홈 | 맨 위 검색바, 음식 종류 아이콘 4열, 추천 줄 "지금 바로 줄 설 수 있어요", "오늘 저녁 7시, 2명 자리 있어요"(검색 API 로 오늘 19시 2명 조회), 모든 매장 블록 목록 |
| 매장 카드 | 목록 응답에 사진이 없어 카테고리 그림 칸 + 이름, 카테고리, 주소 |
| 검색 | 회색 바탕, 조건 입력을 둥근 검색바 모양으로, 결과를 흰 블록으로 |
| 마이다이닝 | 탭 전체/웨이팅/예약(`?type=`), 날짜별 흰 블록에 묶어 최근 날짜부터, 항목마다 굵은 상태 + 방문일 또는 대기번호, 상세·취소·리뷰 버튼 |
| 매장 상세·알림·점주 목록 | 메뉴, 리뷰, 알림, 점주 예약·웨이팅·매장 목록을 둥근 블록으로 |
| 문구 | 화면·목 알림 문구의 `·` 를 쉼표나 문장으로 바꿈 |

판단: 추천을 "거리순", "인기순"으로 만들려면 위치와 평점·인기 데이터가 필요한데 백엔드 목록 응답에 없다. 지금은 백엔드 값(웨이팅 가능, 오늘 저녁 빈자리)으로만 추천하고, 거리·인기는 백엔드 요청 목록에 둔다.

검증: `npm run lint`, `npm run build` 통과. Playwright(414px, 목 API)로 고객 9개, 점주 5개 화면 확인.

## 후속 2 (2026-10-29): 문구, 검색, 점주 화면 진입

- 문구: "줄 서기 가능"을 "웨이팅 가능"으로 (매장 태그, 홈 추천 줄, 점주 웨이팅 접수 상태, 다시 신청 버튼).
- 검색: 제목을 "검색"으로. 맨 위는 식당 이름 입력, 날짜·시간·인원은 그 아래 부가 조건 버튼(고르면 빈자리와 예약 가능 시간 표시). 이름 검색은 백엔드 조건에 없어 받은 목록을 화면에서 거른다 (앞 기록에서 지운 키워드 검색을 사용자 요청으로 다시 넣음, `?q=`).
- 점주 화면이 안 열리던 문제: 고객 화면에서 시작 화면으로 넘어온 뒤 "점주로 시작"을 누르면 원래 가려던 고객 화면으로 돌아갔고, 점주 상태에서도 홈이 고객 화면이었다. 돌아갈 화면은 고른 회원 유형과 맞을 때만 쓰고, 점주가 고객 화면에 오면 점주 화면으로, 고객이 점주 화면에 오면 시작 화면으로 보낸다. 시작 화면에는 지금 이용 중인 회원을 표시.
- 검증: lint, build 통과. Playwright 로 진입 4가지(비로그인 → 점주, 점주 상태로 홈, 고객 상태로 점주 화면, 이어서 점주로 시작)와 이름 검색 확인.
