# 2026-11-09 점주 웨이팅 흐름 (와이어프레임 반영)

와이어프레임의 점주 웨이팅 현황, 웨이팅 설정 화면과 백엔드 dev(`a44952e`)의 새 웨이팅 API를 연결했다.

## 버그 수정

- 착석 처리 `POST /api/owner/waitings/{id}/enter`가 본문 없이 호출되고 있었다. 백엔드는 `WaitingEnterRequest { tableId }`(필수)를 받으므로 실제 서버에서는 400이 났다. 이제 테이블을 골라 `{ tableId }`를 보낸다.
- 목록을 접수번호로 다시 정렬하던 코드를 뺐다. 서버가 순번 연기를 반영한 대기 순서(queue_order)로 내려주므로 그 순서를 그대로 쓴다 (백엔드 문서 feature-47 요청).

## 추가

- 착석 테이블 선택 시트: 응답의 `compatibleTables`(인원에 맞는 운영 중 테이블)를 보여주고 고른 테이블로 착석 처리한다. 실제 공석 여부는 응답에 없어 점주가 확인하도록 안내했다.
- 호출 다시 보내기 `POST /recall`
- 한 팀 뒤로 `POST /defer` — 성공하면 "N번째 순서로 미뤘어요 (1/2)" 안내, 409(`WAITING_NOT_DEFERRABLE`, `WAITING_DEFER_LIMIT_EXCEEDED`)는 서버 메시지를 그대로 보여준다.
- 웨이팅 카드 재구성 (팀 리뷰 댓글 반영)
  - 머리에 "12번" + 상태 배지, 아래에 "이름, 인원"과 접수, 호출 시각
  - 호출된 카드는 상태 줄 한 칸: 응답 대기(남은 시간), 가는 중 응답(응답 시각, 제한 시각), 제한시간 지남(지난 분, 배지 "응답 없음")
  - 버튼은 두세 개로 줄임. 노쇼 처리는 제한시간이 지난 카드에만 나온다
- 웨이팅 설정 화면 `/owner/stores/:storeId/waitings/settings` — 도착 제한시간 5/10/15/20/30분, 저장. 매장 홈에 "웨이팅 설정" 항목을 추가하고 현황 화면의 "도착 제한시간 바꾸기" 링크는 뺐다.

## MSW 목

- `/recall`, `/defer` 추가, `/enter`는 `tableId` 필수와 테이블 검사
- 대기 순서 `queueOrder`, 연기 횟수 `deferCount` 추가
- 데모 대기열 진행에서 호출할 때 호출 시각, 제한시각을 같이 채움

## 확인

- `tsc --noEmit`, `oxlint`, `vitest run`(31개) 통과
- MSW 목으로 점주 로그인 후 웨이팅 현황(한 팀 뒤로, 착석 테이블 선택, 착석), 매장 홈, 웨이팅 설정을 확인. 실제 백엔드에서는 아직 확인하지 않았다.
